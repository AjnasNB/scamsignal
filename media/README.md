# ScamSignal + AppPassport media

Public presentation assets for the APK evidence demo at
https://scamsignal.ajnasnb.com.

- `brand/scamsignal-mark.png`: transparent logo.
- `images/`: original generated illustrations for India, APK evidence, and independently readable records.
- `deck/scamsignal-pitch-deck.pptx`: seven-slide editable presentation.
- `deck/slide-1.png` through `slide-7.png`: presentation previews.
- `video/scamsignal-explainer.mp4`: 2m 02s narrated motion graphics and recorded live product demonstration (1080p, 30 fps, stereo audio).
- `video/poster.png`: video cover image.

The visual artwork was generated for this project. Music was originally synthesized for the film. Narration is synthetic, generated locally with [Kokoro](https://github.com/hexgrad/kokoro) (Apache 2.0) using [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx) (MIT). Sound effects use [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds) under CC0. The film uses [DM Sans](https://github.com/googlefonts/dm-fonts) and [Noto Sans Devanagari](https://github.com/notofonts/devanagari), both under the SIL Open Font License. Fonts and model weights are not redistributed in these finished media files.

The presentation includes twelve measured APKs: five upstream releases, five documented historical malware samples, and two intentionally vulnerable training applications (InsecureBankv2 and PIVAA). All twelve signatures verify. Malware classifications are tied to published primary research and artifact identifiers; they are not inferred solely from requested permissions. Nineteen actual public Arkiv records contain twelve artifact references and seven advisories.

The film's upload sequence records a real InsecureBankv2 upload without installing or executing it. The historical Fake BtcTurk case is visibly labelled a precomputed measured report with a fresh live Arkiv lookup. Viewer and Hindi sequences are recordings of the deployed website. Motion graphics illustrate package structure and independent record reads. Signature verification and permission declarations do not establish application safety. New scans require the analysis service; existing public warning records can be read independently.
